# 05 — UI · VíaClara

Dueño del sistema de diseño: **P4**. Mobile-first (conductor, portal, oficial); desktop-first solo en `/camaras` y `/admin`.

## 1. Dirección de diseño
**Sobrio, cívico, confiable** — como un servicio público bien hecho (referencias de tono: GOV.UK, USWDS), no como una startup genérica.
- **Prohibido**: degradados morados/azules, glassmorphism, Inter por defecto, íconos emoji, ilustraciones 3D, "sparkles ✨ IA", sombras difusas grandes, tarjetas flotantes sin propósito.
- **Sí**: tipografía con carácter institucional, mucho contraste, jerarquía clara, bordes nítidos, datos tabulares en mono, colores de señalización vial usados con significado (rojo = infracción/pendiente, verde = pagado, ámbar = en revisión).
- La evidencia es protagonista: fotos grandes, con hora y estado del semáforo superpuestos.
- Lenguaje: claro, sin jerga, "usted" en comunicaciones oficiales. Siempre visible "Demo — datos ficticios, pagos simulados".
- Íconos: `lucide-react` (trazo 1.75), nunca emoji.

## 3. Pantallas
### 3.1 `/` Landing (P4)
Hero sobrio: nombre, una línea, 3 accesos: "Consultar por cédula", "Soy oficial", "Consola de cámaras". Explicación de 3 pasos (Detecta → Notifica → Paga). Sin stock photos.
**AC**: carga < 1 s en 4G; Lighthouse accesibilidad ≥ 95.

### 3.2 `/camaras` Simulador + consola (P2)
Layout desktop 2 columnas:
- Izquierda: selector de cámara (código + intersección), canvas con frame y overlay de `stopLine`/`lightRoi` (editable arrastrando puntos, guarda con PATCH), dropzone para 2–3 imágenes, botón "Sets de demo" (A: luz roja con placa legible, B: verde sin infracción, C: placa ilegible, D: vehículo con deuda), botón primario **Analizar**.
- Derecha: **feed en vivo** (polling 2–3 s) de detecciones: miniatura, `<SemaforoMini>`, `<Placa>`, confianza (barra), veredicto, estado (DETECTED→NOTIFIED animado por pasos), link a multa. Panel de "Alertas a oficiales" recientes.
- Estado de análisis paso a paso: "Subiendo frames → Analizando con IA → Validando regla de línea → Creando multa → Enviando WhatsApp".
**AC**: set A produce VIOLATION + multa + WhatsApp en ≤ 20 s; set B NO_VIOLATION; set C NEEDS_REVIEW; set D genera alerta.

### 3.3 `/multa/[token]` Aterrizaje de multa (P3, componentes P4)
Mobile: `<DemoBanner>` → título "Aviso de infracción" → `<EstadoBadge>` → tipo + fecha/hora + intersección → `<Evidencia>` → `<Placa masked>` + vehículo → `<Monto>` + vencimiento → CTA rojo "Pagar con Pago Móvil C2P" → link secundario "Apelar" (stretch) → "Verificado automáticamente / por operador" + cómo se detectó (texto corto).
Si `PAID`: badge verde, comprobante con referencia `SIM-…`, sin CTA.
**AC**: legible a 360 px; evidencia carga lazy; sin cédula/teléfono visibles.

### 3.4 `/multa/[token]/pagar` Pago C2P simulado (P3)
Form de 4 campos: Banco (Select con lista de ejemplo), Teléfono (`0412…`), Cédula (`V`/`E` + número), Clave C2P (input numérico, `autocomplete="one-time-code"`). Ayuda: "Genere su clave C2P en la app de su banco" (texto genérico). Resumen de monto arriba. Botón "Pagar {monto}". Estados: enviando (spinner + texto), aprobado (pantalla de comprobante grande: referencia, fecha, monto, "simulado"), rechazado (mensaje claro + reintentar).
**AC**: validación inline en español; doble clic no genera doble pago (idempotencyKey); banner de simulación visible en todo momento.

### 3.5 `/consulta` Portal por cédula (P4)
Input grande con prefijo `V/E`, botón "Consultar". Resultado: resumen (total / pendientes / pagadas) + lista de tarjetas (fecha, tipo, intersección, `<Placa masked>`, `<EstadoBadge>`, monto). Nota de privacidad visible: "Mostramos información limitada. Para ver evidencia use el enlace recibido por WhatsApp" (+ OTP stretch). Estado vacío neutro.
**AC**: misma respuesta visual para cédula inexistente y sin multas; mensaje claro al ser limitado (429).

### 3.6 `/oficial` Vista móvil del oficial (P4 UI, API P3)
Login por passcode + selección de placa de oficial. Header con toggle **En servicio**. Mapa Leaflet (OSM) con: posición propia, cámaras, alerta activa (marcador de la **cámara** donde se vio el vehículo). Lista de alertas (tarjeta: `<Placa>` completa, vehículo, # multas impagas, intersección, distancia, "hace X min", botón "Recibido"). Botón "Usar posición demo". Vibración/sonido corto al llegar alerta (si permitido).
**AC**: alerta aparece ≤ 5 s tras dispararse (polling 3 s); funciona sin permitir geolocalización (posición demo); nunca muestra datos del dueño (nombre/dirección/cédula).

### 3.7 `/admin/revision` Cola de revisión (P4 UI, API P1)
Tabla/lista de `NEEDS_REVIEW` con motivo (badge ámbar). Detalle en Sheet: frames grandes, salida de IA (estado por frame, placa, confianza, notas), resultado de regla geométrica, input editable de placa, botones **Aprobar y multar** / **Anular** (motivo obligatorio). Historial de auditoría de la violación.
**AC**: aprobar crea multa y dispara WhatsApp; anular pide motivo; ambas acciones aparecen en `AuditLog`.

## 4. Accesibilidad y calidad
- Contraste AA mínimo; foco visible; labels reales; tamaños táctiles ≥ 44 px.
- Estados de carga con Skeleton, errores con mensaje accionable.
- Fechas `Intl.DateTimeFormat("es-VE", { timeZone: "America/Caracas" })`.
- Usar skills `frontend-ui-engineering`, `minimalist-ui`, `web-design-guidelines`, `vercel-react-best-practices`; documentar decisiones en `DESIGN.md` con skill `design-md`.
